# Handoff, 2026-07-21

Follows `HANDOFF_2026-07-20-NIGHT.md`.

Two backend deploys went out. Everything else is in the working tree, tested,
and not deployed.

## Start here

Three things found today are worse than anything on the open list, and two of
them were live.

**1. The Kotlin admin was deleting fields on every household save.**
`AuntieRepository.updateKinfolk` used a bare `.set()`, which replaces the whole
document, so every field the backend writes but the Kotlin model does not
declare was erased by an ordinary save. Measured against MyTribe, that is
`myTribeLinkedAt` (portal auth linkage, `revokeKinfolkClaim.ts`), `isTestData`
(the sandbox marker, `familyProvision.ts`), and `businessName` (read by
`getMyHome.ts`). Losing `isTestData` silently breaks sandbox isolation.

The existing comment on that line shows the shape of the problem: `updatedAt`
was added to the model *because a save had already destroyed it*. That was a
one-field patch on a whole class of bug. Four update paths now use
`SetOptions.merge()` (kinfolk, kin, household_data, invoices). Every modelled
field still ships, blanks included, because the data class serialises them, so
merge costs nothing. 1426 android tests green.

**2. A Kin has been invisible in the admin.** `KIN_QUERY` ordered by
`updatedAt`, and Firestore drops documents missing the sort field. Live coverage
is 23 of 24. No field is written by every writer (android `createKin` does a
whole-object add, this admin's `createKin` never writes `familyKinPath`), so
there was no safe field to switch to. Both kin queries now order by document id,
the one key every document is guaranteed to have. The Care Flags widget was the
worse victim: it skips unresolvable kin, so it rendered a confident "No special
care notes for today's roster" while dropping one.

**3. Six golden screenshots are pictures of a broken screen.** See
`docs/reviews/2026-07-21-golden-screenshot-triage.md`. `android/home` at 78.9%
was not drift, it was a crash: two fail-loud banners and every widget gone,
because the test never stubbed `getKinCareSessions()` or `getAllKin()` and the
relaxed mock's bare `Object` died at the `List` cast. Fixed and recaptured.
The five desktop ones are the same class ("Not signed in" banners from
unfixtured reads) and are still open.

## Deployed

`generateAuntieCopy`, twice, both verified.

- `recipient` is now optional and NOT gated on `communication_type`. Broadcast
  sends as `email` with no single recipient and was being rejected. Empty
  recipient skips the Kinfolk resolution entirely; a recipient that IS supplied
  but matches nobody still 404s.
- `want_title` returns a headline drawn from the generated body, reusing
  `TITLE_INSTRUCTION` verbatim from MyTribe's backfill so live and backfilled
  titles read alike. KNOWN DIVERGENCE, documented at the constant: the backfill
  runs it on `claude-opus-4-8`, this function's allowlist has exactly one member,
  `claude-sonnet-4-5`. Same instruction, not the same voice.

A correction to the previous handoff: it listed "blog generation is broken" as
an open item, and the recipient fix was described here as fixing it. React has
no blog surface at all, only email and sms. `blog_post` exists solely in the
throwaway wasm enum. The fix is right, but Broadcast was the live thing it
unblocked. Blog was noise.

## Built, tested, NOT deployed

React admin, 143 files / 2048 tests, `tsc` clean, production build green.

- **Toast system.** `ToastTone` has no `error` member by design. Errors stay in
  `Banner`/`AsyncRegion`, which persist; a self-dismissing failure is a swallowed
  failure. A `@ts-expect-error` test fails to compile if anyone widens it.
- **Zod**, now a real dependency rather than hand-mirrored comments.
  `kinTaleDraftSchema` is the pattern to copy.
- **Ask Auntie** beside the KinTale body. Fills a BLANK headline only; a
  headline the operator typed is never overwritten, and any keystroke clears
  `titleGeneratedByAi`. That field did not exist in this repo and is now on
  `KinTaleDraft` and the write path.
- **HouseholdData** and **KinfolkEdit**, the only two genuine web parity gaps.
  Both reached from `KinfolkProfile` by local state, matching how Directory
  already opens the profile. The other three screens the 07-20 handoff called
  missing were wrong: TemplateBank fully exists (web is ahead, three callables
  Kotlin lacks), TrainingDocuments and KinTaleLogs are partial.
- **Broadcast gained push.** The backend always supported four channels
  (`inapp`, `email`, `sms`, `push`); the UI exposed two. Push is a real FCM
  multicast counted per recipient. `inapp` is still unexposed and genuinely
  needs design: it requires a subject and writes a notification doc the portal
  feed consumes.
- **Secrets are masked.** `gateCode` and `wifiPassword` were plaintext on the
  Home dashboard. Mask is a fixed six glyphs, never one per character, because a
  per-character mask publishes the length.
- **Tribal Intel**: suppressed for sandbox accounts (the rule grants no
  test-admin read, so no query predicate could buy one), and the sort moved to
  `uploadedAt`, which every writer stamps. `createdAt` is not on the Kotlin
  model at all, so android-written docs were invisible.
- **vetInfo** is no longer editable on the Kin, per the standing rule that vet
  attaches to the household. Read-only display stays.

## Gotchas

- `userEvent` deadlocks under fake timers even when handed `advanceTimers`. The
  test times out instead of failing, which reads as flake. Use `fireEvent` in
  those blocks.
- `:composeApp:jvmTest` still rewrites tracked goldens under `visual/desktop/`.
  `:app:testDebugUnitTest` no longer does: the Roborazzi record flag reads a
  gradle property and defaults to false. Pass `-Proborazzi.record` to capture.
- `loud-build.sh` lives at the repo root but `gradlew` is under `web/` for the
  Compose project and `android/` for the app. Running it from the wrong
  directory fails with exit 127.
- The functions test double never filtered: `get()` closed over `api._filters`
  instead of `this._filters`, so every `.where()` in that suite matched
  everything. The fixture hid it because all its Kin share one `kinfolkId`.
