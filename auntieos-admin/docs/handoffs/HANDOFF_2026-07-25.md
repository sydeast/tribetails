## Start here

**Partial payments are broken, and the balance is unrecoverable.** This is the
only item below where the CURRENT behaviour costs money, so it goes first.

`mytribe/functions/src/admin/markInvoicePaid.ts` accepts a partial `amount` and
records the `payments` subcollection doc correctly. Then it writes, without any
condition on how much was actually paid:

```ts
batch.set(ref, { status: 'paid', amountDue: 0, ... }, { merge: true });
```

So $20 against a $40 invoice leaves the invoice reading PAID with $0 due. It
drops out of Outstanding and nobody chases the rest. And because
`isAlreadyPaid(d)` returns true on `status === 'paid'` and the handler throws
`failed-precondition` on it, the SECOND call to collect the remaining $20 is
REFUSED. There is no way to record the balance.

PR #72's edit gating compounds it: once ANY payment exists, money fields freeze,
so `updateInvoice` cannot repair it either. That freeze is right for a settled
invoice and wrong for a part-paid one.

**Check production data before assuming it is clean.** Any invoice with
`status: 'paid'`, `amountDue: 0`, and a `payments` subcollection summing to less
than `total` is already in the corrupt state.

## What the week found, so it is not re-learned

Each of these was invisible from an audit and only surfaced by trying to fix
something next to it.

**Fraunces had never rendered since the port.**
`@fontsource-variable/fraunces` registers the family as `Fraunces Variable`;
`tokens.css` asked for `Fraunces`, which nothing declares. Every serif heading in
the admin fell through to Georgia while the real face downloaded on every page
load. Almost certainly the largest single cause of the "the port feels flat"
report, and no unit test could have seen it.

**Eleven tokens were referenced but never declared**, not the three a targeted
grep found. `--type-label-family` / `-size` / `-tracking` were the worst: the real
names carry an `-md` or `-sm` step, so the vet clinic picker, breed field and
address autofill rendered their labels with no face, size or tracking at all.
`src/styles/tokenUsage.test.ts` now fails the build on any undeclared reference
and on any literal fallback for a global token, which is what let all of it hide.

**Body text inherited Kinfolk Orange.** `base.css` set `color: var(--color-primary)`
whose `#1a1c28` fallback recorded that navy was meant. Same swap in eight more
places, including a modal backdrop mixing a 45% ORANGE scrim over the page.

**The Android date picker booked visits a day early east of Greenwich.** It
seeded through `ZoneId.systemDefault()` and read back through `ZoneId.of("UTC")`.
Seeding 2027-08-16 in Auckland yields `2027-08-15T12:00Z`, so the picker opened
on the day before the one it was handed.

**Two CSS cascade bugs, both found by reading the EMITTED bundle** rather than
the source. `.signin__card` tied `.glass-surface` on specificity and lost on
emit order, and `.bookings__row-main--static:hover` was declared before the rule
it was meant to override, so the static row took the hover fill anyway.

**The calendar Run Sync button reported into a void.** Its only record was a
non-client-readable audit entry, so the operator pressed it and had to go hunting
on the Schedule for blocks that may or may not have appeared. It now stamps a
receipt on success and on failure. Also confirmed while there: that sync has NO
trigger and NO schedule. Nothing refreshes busy blocks on its own.

**A near miss worth keeping.** The rail's unread count pill was nearly shipped
with a permanently empty source, which is the gate-dark `CLAUDE.md` forbids. The
obvious data source, `listConversations`, is a one-shot, and reading a thread
clears `unreadForAdmin` server-side, so a page-load snapshot pinned to the chrome
would have claimed four unread on every screen after the operator had read all
four. A number that is wrong everywhere is worse than no number.

## Firestore traps now documented in code, all silent failures

- `where('invoiceId','==','')` misses every session written by
  `createKinCareSession` or `approveBookingSeriesCore`, because neither writes
  the field and equality SKIPS documents that lack it.
- `where('archivedAt','==',null)` matches only documents that HAVE the field, so
  on a collection where nothing has been archived yet it returns ZERO rows.
- Invoices must page on `date`, not `createdAt`. `createdAt` is a real Timestamp,
  Firestore orders every timestamp after every string, so an ISO-string bound
  matches nothing and does not error.
- `kin_care_sessions.startTime` is an ISO STRING. Range-query it lexically.
- `status` casing is unenforced everywhere. Normalize in memory rather than with
  a server equality, or a visit stored as `completed` is invisibly dropped.
