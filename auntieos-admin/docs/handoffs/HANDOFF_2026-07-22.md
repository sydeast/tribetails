## Deployed to prod today

Verified by comparing the live served bundle hash to the fresh build, not by
trusting a deploy exit code.

- **React admin** (`hosting:app`, auntie.tribetails.com). Live bundle
  `index-CzwKKji3.js` matches the build. Carries every 07-21 feature and the
  Sentry wiring.
- **Kinfolk portal** (`hosting:kinfolk_portal` = kinfolk.tribetails.com, and
  `hosting:mytribe_beta`). Live bundle `index-pso5MflX.js` matches. Carries the
  portal Sentry wiring and header parity.
- **MyTribe functions** (`functions:mytribe`). First pass reported "Failed to
  update" on 16 of the codebase functions; that is transient Cloud Functions
  update contention, and a failed update keeps the prior working revision, so
  prod never went down. A targeted retry of exactly those 16
  (`--only functions:mytribe:assignAuntie,functions:mytribe:stripeWebhook,...`)
  came back clean.
- **AuntieOS default functions** (`functions:default`, from `auntieos-admin/web`)
  clean.
- Firestore rules and indexes were NOT redeployed: unchanged since 07-20 and
  already live. `reconcile` (python) unchanged, not redeployed.

Two lessons banked into the SOTU environment traps: never pipe a deploy to
`tail` (it masks the exit code and hides a partial functions failure behind a
green wrapper), and a functions "Failed to update" on a subset is a retry, not a
failure.
